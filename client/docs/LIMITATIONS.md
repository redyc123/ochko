# Известные ограничения

Статус на момент написания: готовы Этап 0 (каркас, подключение) и Этап 1
(навигатор). Ниже — что не работает, что не измерено и что нужно сделать для
продакшна. Цифр без измерения здесь нет; где оценка — явно помечено.

## Что не проверено в этой сессии разработки

- **Не было реального железа** (очков на ESP32-C6) и Android SDK/эмулятора в
  среде, где писался код. Протокол (`src/ble/protocol`) проверен байт-в-байт
  тестами с hex-примерами из `docs/PROTOCOL.md`, вся логика трекинга/навигации
  и UI-сторы — модульными тестами Jest (218/218 зелёных, `tsc --noEmit` и
  ESLint без ошибок). Но ни `expo prebuild`, ни сборка APK, ни запуск на
  реальном устройстве/эмуляторе Android **не выполнялись** — перед защитой
  это нужно проверить руками.
- Экраны (`DeviceScreen`, `NavigationScreen`, `EmulatorScreen`) не тестировались
  визуально — по ТЗ UI тестами не покрывается, но и глазами в симуляторе их
  никто не видел. Сборка `expo prebuild`/первый запуск может потребовать
  мелких правок (разрешения, версии Gradle и т.п.).
- Сопряжение по Passkey Entry реализовано против официального API
  `react-native-ble-plx` (коды ошибок `BleATTErrorCode`), но ни разу не
  проверялось против настоящего GATT-сервера с флагами
  «только зашифровано и аутентифицировано».

## iOS

- Приложение собирается под iOS тем же кодом (Expo, без платформенных веток в
  логике), но в этой сессии сборка под iOS не запускалась (нет Xcode в среде
  разработки) — название пакета/bundle id в `app.json` указаны, но не
  проверены.
- **Уведомления (Этап 2, когда будет сделан) на iOS не будет пересылать
  приложение** — очки на iPhone получают уведомления сами через ANCS
  (Apple Notification Center Service). Это ограничение платформы, не нашего
  кода: ANCS работает только между iPhone и подключённым аксессуаром напрямую.
- Голосовая активация стартовым словом работает на самих очках независимо от
  платформы телефона — здесь ограничений iOS нет.
- Фоновая работа на iOS ограничена `UIBackgroundModes` (`bluetooth-central`,
  `location`) — iOS может сильнее дросселировать фоновые GPS-обновления, чем
  Android foreground service; это стандартное ограничение платформы, не
  отдельная недоработка.

## Публичные сервисы (лимиты)

- **Nominatim** (`nominatim.openstreetmap.org`): жёсткий лимит **1 запрос в
  секунду** на источник, требует осмысленный `User-Agent` — у нас стоит
  заглушка-контакт (`src/store/navStore.ts` → `NOMINATIM_USER_AGENT`),
  **замените перед реальным использованием**. Для продакшна — свой сервер
  Nominatim или геокодер с SLA.
- **Valhalla** (`valhalla1.openstreetmap.de`): публичный демо-сервер без
  гарантий доступности/скорости, используется только для разработки и защиты.
  Для продакшна — свой инстанс Valhalla (или подмена `Router` на OSRM/
  GraphHopper — интерфейс уже это позволяет, см. `src/nav/router.ts`).
- **Тайлы карты** (`tile.openstreetmap.org`, raster): по политике OSMF эти
  тайлы **нельзя** встраивать в массово распространяемое приложение — это
  тайл-сервер для разработки/личного использования. Для продакшна нужен
  коммерческий провайдер (MapTiler, Thunderforest, Mapbox) или свой
  тайл-сервер.

## Протокол и эмулятор

- Иконки манёвров в эмуляторе — Unicode-символы-заменители (`src/emulator/render.ts`),
  не настоящий растровый шрифт 6×8 / иконки 24×24, которые рисует прошивка.
  Пиксель-точного превью без ассетов прошивки сделать нельзя.
- `audio`-кадры (ADPCM, §4.5 протокола) в текущей версии не кодируются и не
  декодируются — это задача Этапа 3. Протокол для них задокументирован в ТЗ,
  но `src/ble/protocol` их пока не реализует.
- Распознавание манёвров Valhalla → иконка протокола покрывает типы 0..36 на
  момент написания (сверено с документацией, не по памяти). Если Valhalla
  добавит новые типы (лестницы/эскалаторы и т.п.), неизвестный тип уйдёт как
  `ManeuverIcon.NONE` — на экране будет просто текст улицы без иконки
  (это предусмотрено, не крэш).

## Что не сделано (следующие этапы по ТЗ)

Этапы 2–6 не реализованы: уведомления, приём и декодирование звука с очков,
интерфейс `SpeechToText`, LLM-агент и инструменты, голосовой отпечаток
владельца, экран «Испытания» с замерами для диплома. Структура папок под них
создана по ТЗ, код — нет. Пошаговый план — в `docs/PLAN.md`.

## Оценки (не измерено)

- Радиус viewbox для геокодинга (`VIEWBOX_DELTA_DEG = 0.05°` ≈ 5.5 км) —
  оценка для поиска «рядом», не калибровалась по реальным сценариям.
- Пороги трекинга (сход с маршрута 30 м / 10 с, прибытие 15 м, таймаут GPS
  10 с) взяты прямо из ТЗ как константы по умолчанию — не перепроверялись на
  реальных GPS-треках.
