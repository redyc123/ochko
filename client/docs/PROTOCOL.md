# Протокол О.Ч.К.О. (версия 1)

Это контракт между приложением и прошивкой очков. Если формат нужно поменять —
меняем этот файл и `PROTOCOL_VERSION`, а не «тихо» байты.

Порядок байт — **little-endian**. Строки — UTF-8 без нулевого терминатора, с
префиксом длины (1 байт = длина в байтах, не в символах).

Все примеры ниже сгенерированы кодерами из `src/ble/protocol/*` и byte-в-byte
проверяются тестами в `src/ble/protocol/*.test.ts` — это один и тот же источник
истины, он не может «разойтись» с документом.

## 1. Сервис и характеристики

Базовый UUID: `1277XXXX-4f16-4cec-abf9-1d12f945b15b`.

| XXXX | Имя | Направление | Свойства |
|---|---|---|---|
| `0001` | сервис О.Ч.К.О. | | |
| `0002` | `display` | телефон → очки | Write (with response) |
| `0003` | `events` | очки → телефон | Notify |
| `0004` | `audio` | очки → телефон | Notify |
| `0005` | `control` | телефон → очки | Write (with response) |
| `0006` | `info` | очки → телефон | Read |

Все характеристики требуют шифрования и аутентификации (LE Secure Connections
+ bonding, см. `docs/LIMITATIONS.md` про Passkey Entry).

## 2. Общий заголовок (`display`, `events`, `control`)

```
offset size поле
0      1    ver      = 1
1      1    type     тип сообщения
2      1    flags    бит0 = продолжение (не последний фрагмент), бит1 = последний фрагмент
3      1    seq      номер сообщения 0..255 по кругу, свой на каждое направление
4      ..   payload
```

Нефрагментированное сообщение — `flags = 0x00`.

### Фрагментация

Если `payload` не влезает в `MTU − 3 − 4` байт, он режется на кадры с одним и
тем же `seq`: все кадры кроме последнего — `flags = CONTINUATION (0x01)`,
последний — `flags = LAST_FRAGMENT (0x02)`. Получатель копит payload по `seq`,
пока не придёт кадр без бита `CONTINUATION` (то есть обычный нефрагментированный
пакет и последний кадр фрагментированного — это один и тот же случай).
Реализация: `fragmentPacket` / `PacketReassembler` в `src/ble/protocol/fragment.ts`.

## 3. `display`: типы сообщений

| type | Имя |
|---|---|
| `0x01` | `NOTIFY` |
| `0x10` | `NAV_MANEUVER` |
| `0x11` | `NAV_PROGRESS` |
| `0x12` | `NAV_STATE` |
| `0x20` | `AGENT_STATE` |
| `0x21` | `AGENT_TEXT` |
| `0x22` | `CONFIRM` |
| `0x7F` | `CLEAR` |

### 3.1. `NOTIFY` (0x01)

```
app u8        0 прочее, 1 SMS, 2 звонок, 3 мессенджер, 4 почта, 5 календарь
prio u8       0 обычный, 1 высокий
ttl_s u8      0 = до нажатия
title_len u8
title         UTF-8, title_len байт
body_len u8
body          UTF-8, body_len байт
```

Пример — уведомление из Telegram «Мама: позвони», `seq=7`, высокий приоритет:

```
01 01 00 07 03 01 00 08 54 65 6c 65 67 72 61 6d 18 d0 9c d0 b0 d0 bc d0 b0 3a
20 d0 bf d0 be d0 b7 d0 b2 d0 be d0 bd d0 b8
```
hex: `010100070301000854656c656772616d18d09cd0b0d0bcd0b03a20d0bfd0bed0b7d0b2d0bed0bdd0b8`

Разбор: `ver=01 type=01 flags=00 seq=07 | app=03(мессенджер) prio=01 ttl_s=00 title_len=08 "Telegram" | body_len=18(24) "Мама: позвони"`.

### 3.2. `NAV_MANEUVER` (0x10)

```
icon       u8   код манёвра (см. §6)
exit_no    u8   номер съезда с кольца (0, если не кольцо)
dist_m     u16  расстояние до манёвра, м, уже округлённое (0xFFFF = неизвестно)
total_m    u32  оставшееся расстояние до цели, м
eta_min    u16  оставшееся время, мин
street_len u8
street     UTF-8, ≤ 24 байт
```

Пример — «через 150 м налево, ул. Ленина», `seq=3`:

hex: `0110000307009600b0040000120012d183d0bb2e20d09bd0b5d0bdd0b8d0bdd0b0`

Разбор: `ver=01 type=10 flags=00 seq=03 | icon=07(налево) exit_no=00 dist_m=0096(150) total_m=000004b0(1200) eta_min=0012(18) street_len=12(18) "ул. Ленина"`.

### 3.3. `NAV_PROGRESS` (0x11)

```
dist_m   u16
total_m  u32
eta_min  u16
```

Пример, `seq=4`: hex: `011100048c00a60400001200`
(`dist_m=008c(140) total_m=000004a6(1190) eta_min=0012(18)`).

### 3.4. `NAV_STATE` (0x12)

```
state u8   0 выкл, 1 строится, 2 ведение, 3 перестраиваю, 4 нет GPS, 5 прибыли, 6 ошибка
```

Пример «ведение», `seq=5`: hex: `0112000502`.

### 3.5. `AGENT_STATE` (0x20)

```
state u8   0 нет, 1 слушаю, 2 думаю, 3 готово, 4 ошибка, 5 жду подтверждения
```

Пример «думаю», `seq=9`: hex: `0120000902`.

### 3.6. `AGENT_TEXT` (0x21)

```
ttl_s u8
len   u8
text  UTF-8, ≤ 60 символов, листается коротким нажатием
```

Пример, `seq=10`: hex:
`0121000a0a2fd091d183d0b4d0b8d0bbd18cd0bdd0b8d0ba20d0bdd0b020373a303020d0bfd0bed181d182d0b0d0b2d0bbd0b5d0bd`
(`ttl_s=0a(10) len=2f(47) "Будильник на 7:00 поставлен"`).

### 3.7. `CONFIRM` (0x22)

```
id         u8
timeout_s  u8
len        u8
text       UTF-8 (вопрос, например «Позвонить Маме?»)
```

Пример, `seq=11`: hex: `0122000b01051cd09fd0bed0b7d0b2d0bed0bdd0b8d182d18c20d09cd0b0d0bcd0b53f`
(`id=01 timeout_s=05 len=1c(28) "Позвонить Маме?"`).

### 3.8. `CLEAR` (0x7F)

```
layer u8   0 всё, 1 уведомления, 2 навигация, 3 агент
```

Пример «очистить всё», `seq=12`: hex: `017f000c00`.

### Приоритеты отображения

`CONFIRM` > `AGENT_*` > `NAV_*` (когда до манёвра < 50 м) > `NOTIFY` высокого
приоритета > `NAV_*` > `NOTIFY`. Приложение держит этот же порядок в своей
очереди записи в `display`.

## 4. Коды манёвров (`icon`)

Прошивка рисует по ним стрелки 24×24.

| код | манёвр | код | манёвр |
|---|---|---|---|
| 0 | нет / неизвестно | 8 | плавно налево |
| 1 | прямо | 9 | кольцо (с `exit_no`) |
| 2 | плавно направо | 10 | цель прибытия |
| 3 | направо | 11 | старт |
| 4 | резко направо | 12 | лестница / переход |
| 5 | разворот | 13 | держаться правее |
| 6 | резко налево | 14 | держаться левее |
| 7 | налево | 15 | паром / прочий транспорт |

Маппинг типов манёвров Valhalla → эти коды — в `src/nav/maneuverMap.ts`.

## 5. `events`: очки → телефон

| type | Имя | Payload |
|---|---|---|
| `0x01` | `BUTTON` | `kind u8`: 1 короткое, 2 удержание (начало), 3 отпускание, 4 двойное |
| `0x02` | `WAKEWORD` | — |
| `0x03` | `CONFIRM_RESULT` | `id u8`, `result u8` (1 да, 0 нет/таймаут) |
| `0x04` | `BATTERY` | `percent u8`, `mv u16`, `charging u8` |
| `0x05` | `ERROR` | `code u8`, `len u8`, `text` |

Примеры:

- `BUTTON` короткое, `seq=1`: hex `0101000101`
- `WAKEWORD`, `seq=2`: hex `01020002`
- `CONFIRM_RESULT` id=1 да, `seq=13`: hex `0103000d0101`
- `BATTERY` 82%, 4012 мВ, не заряжается, `seq=14`: hex `0104000e52ac0f00`
- `ERROR` code=1 "BLE write timeout", `seq=15`: hex
  `0105000f0111424c452077726974652074696d656f7574`

## 6. `control`: телефон → очки

| type | Имя | Payload |
|---|---|---|
| `0x01` | `SET_TIME` | `unix u32`, `tz_min i16` |
| `0x02` | `BRIGHTNESS` | `level u8` 0..255 |
| `0x03` | `AUDIO_CTRL` | `cmd u8`: 0 стоп, 1 старт записи |
| `0x04` | `CONN_PARAMS` | `mode u8`: 0 экономный, 1 быстрый |

Примеры:

- `SET_TIME` unix=1792000000, tz=+300 мин, `seq=1`: hex `0101000100c0cf6a2c01`
- `BRIGHTNESS` 180, `seq=2`: hex `01020002b4`
- `AUDIO_CTRL` старт, `seq=3`: hex `0103000301`
- `CONN_PARAMS` быстрый, `seq=4`: hex `0104000401`

## 7. `info`: очки → телефон (Read)

```
proto_ver u8, fw_major u8, fw_minor u8, fw_patch u8,
caps u16 (бит0 аудио, бит1 стартовое слово, бит2 навигационные иконки, бит3 кириллица)
```

Пример: протокол v1, прошивка 0.3.1, все возможности есть: hex `010003010f00`.

Если `proto_ver` больше, чем знает приложение — предупредить пользователя и
работать в режиме совместимости (только `NOTIFY` и `CLEAR`).
