# О.Ч.К.О. — мобильное приложение

Приложение-компаньон для смарт-очков О.Ч.К.О. (дипломный проект «Разработка
модульной платформы бюджетных смарт-очков на основе серийных компонентов»).
Вся «умная» часть — навигация, уведомления, распознавание речи, LLM-агент,
проверка голоса — живёт здесь, очки — только экран 72×40, микрофон и кнопка.

Это ТЗ-проект, доведённый до конца **Этапа 0** (каркас и подключение к очкам)
и **Этапа 1** (навигатор): протокол, эмулятор очков, геокодинг/роутинг,
ведение по маршруту, симуляция поездки, экраны «Устройство» и «Навигация».
Этапы 2–6 (уведомления, аудио/STT, LLM-агент, голос владельца, замеры) —
следующий шаг, план по ним — в `docs/PLAN.md`, известные ограничения — в
`docs/LIMITATIONS.md`.

## Стек

- **Expo (SDK 58) + dev client**, TypeScript strict. Expo Go **не подходит** —
  приложению нужны нативные модули (`react-native-ble-plx`, карты, Keychain),
  поэтому сборка идёт через `expo prebuild` + dev client, как и предписывает ТЗ.
- BLE: `react-native-ble-plx`.
- Геолокация: `expo-location`.
- Карта: `react-native-maps` + `UrlTile` на тайлах OpenStreetMap (а не MapLibre —
  см. «Принятые решения»).
- Состояние: `zustand`.
- Навигация по экранам: `@react-navigation/native` + `native-stack`.
- Тесты: Jest (`jest-expo`). 218 тестов на чистую логику протокола, геометрии,
  трекинга, эмулятора и сторов.
- Линт/формат: ESLint 9 (flat config) + Prettier, `tsc --noEmit` без ошибок.

## Установка и запуск

```bash
cd client
npm install

# Разработка с эмулятором очков (не требует нативной сборки/Android SDK —
# работает в Expo Go тоже, если не трогать экран «Устройство» → режим BLE):
npm start

# Полноценная сборка под Android (нужны Android SDK/NDK, подключённое
# устройство или эмулятор — в этой сессии разработки такая сборка
# не запускалась, см. docs/LIMITATIONS.md):
npx expo prebuild --platform android
npm run android      # или: cd android && ./gradlew assembleDebug
```

Проверки без эмулятора/устройства:

```bash
npm run typecheck   # tsc --noEmit
npm run lint         # eslint .
npm test             # jest
npm run test:coverage
```

### Где вписывать ключи/URL

Все внешние сервисы настраиваются через URL (не хардкод):

| Сервис | Где | По умолчанию |
|---|---|---|
| Nominatim (геокодинг) | `src/store/navStore.ts` → `NavSettings.nominatimBaseUrl`, меняется через `useNavStore().setSettings()` | `https://nominatim.openstreetmap.org` |
| Valhalla (маршрутизация) | `NavSettings.valhallaBaseUrl` | `https://valhalla1.openstreetmap.de` |
| User-Agent для Nominatim | `src/store/navStore.ts` → `NOMINATIM_USER_AGENT` | заглушка — **замените на свой контакт** перед реальным использованием (правила публичного Nominatim это требуют) |

Ключей LLM/STT/голосового отпечатка в этой версии ещё нет — появятся в этапах
3–5 и будут храниться в `react-native-keychain` (не в коде, не в AsyncStorage),
как требует ТЗ.

### Как запустить эмулятор очков

Эмулятор включён по умолчанию (`useDeviceStore` стартует в режиме `emulator`).
Экран «Устройство» показывает превью экрана 72×40 (увеличенное) и кнопку D1.
Эмулятор декодирует **те же байты протокола**, что ушли бы в реальные очки
(`src/emulator/EmulatorDevice.ts`), — это одновременно и стенд для разработки
прошивки без паяльника, и постоянная проверка самого протокола.

### Как запустить симуляцию поездки

На экране «Навигация»: введите цель → «Найти» → выберите вариант (если
несколько) → «Начать» → включите тумблер «Симуляция поездки» и выберите
множитель ×1/×2/×5/×10. Симулятор (`src/nav/simulate.ts`) подставляет
GPS-позицию вместо реального датчика; вся остальная логика (привязка к
маршруту, манёвры, сход с маршрута) работает так же, как с настоящим GPS.

## Принятые решения

Там, где ТЗ было неоднозначным или противоречило реальному API платформы —
решение и причина:

- **Expo + dev client, а не bare RN.** Так проще получить единую конфигурацию
  разрешений/плагинов (`app.json`) для `react-native-ble-plx`, `expo-location`
  и foreground service, не теряя доступа к нативным модулям через
  `expo prebuild`.
- **Голос через микрофон телефона (п. 1.1.2) = системная диктовка клавиатуры.**
  Стандартная Android/iOS клавиатура уже даёт голосовой ввод по кнопке
  микрофона в `TextInput` — отдельный STT-провайдер для этого не нужен.
  Полноценный интерфейс `SpeechToText` (Yandex SpeechKit/Whisper/Vosk)
  делается в Этапе 3 для звука **с очков**, где системной диктовки нет.
- **Карта: `react-native-maps` + `UrlTile` на тайлах OSM, не MapLibre.**
  `react-native-maps` на Android всё равно использует Google Play Services как
  движок карты (`mapType="none"` только прячет обычные тайлы Google) — для
  продакшна тайлы `tile.openstreetmap.org` нужно заменить на свой/коммерческий
  сервер (политика OSMF не разрешает встраивать их в приложение массово, см.
  `docs/LIMITATIONS.md`).
- **Протокол, фрагментация (§4.2):** нефрагментированный пакет — `flags=0`.
  Получатель копит фрагменты до тех пор, пока не придёт кадр без бита
  `CONTINUATION` — это одинаково корректно обрабатывает и обычный
  (нефрагментированный) пакет, и последний кадр длинного сообщения.
- **`NAV_MANEUVER.street` — это улица ПОСЛЕ манёвра**, т.е. при движении по
  сегменту между манёврами i и i+1 на экран идёт информация о манёвре i+1
  («через 150 м поверните на ул. Ленина» показывает `ул. Ленина` — улицу,
  на которую повернёте, а не ту, по которой идёте сейчас).
- **Округление расстояния (§1.5) применяется к самому `dist_m` в байтах**
  (шаг 5/10/100 м по диапазонам), а не только к текстовому отображению —
  так что u16-поле протокола уже несёт «человеческое» число. Отображение
  «1,2 км» (`formatDistanceRu`) — только для интерфейса приложения.
  Отображает ли прошивка числа ≥ 1000 м как километры — решение прошивки,
  не часть контракта.
- **Кольца (roundabout):** номер съезда (`exit_no`) кладём только при входе в
  кольцо (`ROUNDABOUT_ENTER`, тип 26 у Valhalla) — это тот манёвр, на котором
  Valhalla сообщает `roundabout_exit_count`. Выход из кольца (`ROUNDABOUT_EXIT`)
  отображается как обычное «прямо».
- **Маппинг типов манёвров Valhalla → иконки** сверен с
  `valhalla-docs/turn-by-turn/api-reference.md` (значения 0..36) через
  веб-поиск в момент написания кода, а не по памяти — см. `src/nav/maneuverMap.ts`.
- **Сопряжение (passkey) не требует вызова `createBond()`.** У
  `react-native-ble-plx` нет публичного API для ручного запуска бондинга —
  ОС сама показывает системный диалог с 6-значным кодом при первой попытке
  прочитать/записать зашифрованную характеристику. Наш код просто переводит
  результирующую ошибку (`InsufficientAuthentication`/`InsufficientEncryption`
  и т.п.) в понятное сообщение (`mapBleErrorToMessage`,
  `src/ble/connection.ts`).
- **Эмулятор зеркалит байты даже во время реального BLE-подключения.**
  `DelegatingTransport` (в `src/store/deviceStore.ts`) посылает те же
  закодированные байты в `EmulatorDevice` для превью «тот же рендер, что в
  эмуляторе» (п. 1.6), даже когда реальная передача идёт в настоящие очки —
  это даёт живой контроль протокола во время стыковки с прошивкой.
- **Иконки манёвров в эмуляторе — Unicode-глифы-заменители** (стрелки
  `↑ ↗ → …`), а не настоящий растровый шрифт 6×8/иконки 24×24 прошивки —
  тех ассетов у нас нет, это рисует сама плата. См. `docs/LIMITATIONS.md`.
