# Ограничения прошивки на MicroPython

## Минимальная версия: MicroPython v1.27 (рекомендуется v1.29.0, `ESP32_GENERIC_C6`)

- В v1.26 для C6 в `mpconfigboard.h` выключен `machine.I2S` — микрофон не работает.
- С v1.27 I2S включён, а `CONFIG_ESP_SYSTEM_PMP_IDRAM_SPLIT=n` позволяет нативному эмиттеру RV32
  исполнять код: работают `@micropython.native` и `@micropython.viper`. Кодер ADPCM на чистом
  Python 16 000 отсчётов/с не успевает, поэтому без viper запись звука нереальна.
- `.mpy` нужно собирать `mpy-cross` той же версии (формат `.mpy` привязан к версии).

## Чего не умеет

| Что | Почему | Как обходим |
|---|---|---|
| Стартовое слово (KWS) | нет вычислительного запаса и FPU, нет готового движка | запись запускает приложение по удержанию кнопки; `CAP_WAKEWORD = 0`, события `WAKEWORD` нет. KWS — отдельный модуль на C, протокол готов |
| Запрос параметров соединения | в модуле `bluetooth` нет вызова обновления параметров для периферии | `CONN_PARAMS` только подтверждается `RESULT OK`; интервалом управляет приложение (Android `requestConnectionPriority`) |
| Автоматический light sleep при активном BLE | в сборке MicroPython для ESP32 не включено автоматическое управление питанием с BLE | энергия экономится отсутствием активных циклов: задачи спят на флагах; панель гаснет по `BRIGHTNESS 0` или `show_no_link=False` |
| Пересогласование MTU по своей инициативе на всех ОС | `gattc_exchange_mtu` для периферии может быть отклонён | MTU отслеживается по `_IRQ_MTU_EXCHANGED`; при MTU < 169 запись не стартует (`ERROR 2`) |
| Нативный эмиттер на хосте arm64 | у MicroPython нет эмиттера для AArch64 | равенство viper/Python проверяется на устройстве или в unix-порту x64 |

## Энергопотребление

Ток MicroPython-прошивки выше, чем у прошивки на C: интерпретатор, отсутствие light sleep
при подключении. Цель «≥ 3 ч от 130 мА·ч» **не гарантирована** и проверяется замером
(`docs/MEASUREMENTS.md`). Все цифры, которые не измерены, являются оценкой.
